### T10 / T11 是新增的，为什么加

交互是 `RendererAdapter` 里最容易被单一实现带偏的部分（DOM 有事件冒泡与 CSS 命中测试，Leafer 有自己的事件系统），差异远大于「画一个矩形」。

**现在是定它最便宜的时刻**——两个渲染器都已完成，两边实现者都能立刻回答「这个回调我这边给得出来吗」。等 P2 开工才定，等于把最难的接口决策推到最贵的时候做。

**T10 不写任何实现代码**，只填问卷（`docs/plans/2026-08-03-P0-T10-交互可行性问询.md`），所以不算扩大 P0 范围。两侧**独立填写、互不可见**，理由同 T6：参照对方答案会让只对一侧自然的设计被抄进契约，缺陷就留下了。

### ⭐ 为什么 P1-7「视觉规格」必须先于 P1-8/P1-9

`ai-image` 有四种状态（`empty` / `pending·running` / `succeeded` / `failed`），每种都要有明确视觉。**如果两侧各自发挥，画出来必然不一样**——而这次的不一样不是「渲染方案的差异」，是「没对齐规格」，会污染对照结论。

P0 的 `box` 不需要这一步（一个纯色矩形没有发挥空间）；业务组件需要。规格要写死的东西：

- 四态各自的布局结构（骨架屏占位、进度指示位置、prompt 摘要条高度、操作条出现时机）
- 尺寸、间距、圆角、颜色的具体值
- **骨架屏必须占住最终尺寸**——否则生成完成时会跳动

**规格是数据，不是实现**：它规定「长什么样」，不规定「用 flex 还是绝对定位」。两侧内部布局仍可各用最优解（`domain.md` §2.2）。

### ⭐ 为什么第二个渲染器必须换一个模型写

这不是负载均衡，是**方法**。

P0 的目的是「用两个实现从两边夹出正确的接口形状」（`docs/lessons.md` #5）。如果两个渲染器由同一个模型写，接口很可能被这一个「脑子」的偏好带偏而**双方都察觉不到**——它会在两侧用同样的思路绕过同一个坑，于是坑留在接口里。

换一个模型写第二个实现，接口里任何**只对第一个实现自然**的设计，都会在第二个实现者手上变成摩擦并被报告出来。**这正是「夹逼」二字的字面含义。**

推论：**T6 的执行方不得阅读 T5 的实现代码**，只读 `@framewright/core` 的接口与计划里 T6 那一节。它必须仅凭接口本身完成实现——接口说不清楚的地方，就是接口的缺陷，要报告而不是靠猜。

## 交接协议

每个任务的执行方必须遵守：

1. **只做分配给你的任务号。** 不许顺手做下一个任务，不许「看到问题顺手改」别的文件。
2. **按计划里给出的步骤顺序执行**，包括「先写失败测试 → 跑一遍确认它真的失败 → 再实现」。不许跳过确认失败那步。
3. **不许改计划。** 发现计划有错、有矛盾、或代码写不出来，**停下报告**，不要自行改设计。计划的修改权在 Claude。
4. **不许扩大范围。** 计划里 `P0 明确不做` 那一节列的东西一律不碰。
5. **commit message 用计划里给定的原文**，不要自己重写。
6. **不许 `git push`。** 只 commit，push 由用户明确指示。
7. **不许用 `--no-verify` 或任何方式绕过校验。** 测试不过就是没做完。

### 完成一个任务的定义

全部满足才算完成：

- 该任务的所有步骤已执行
- 该任务涉及的测试全绿，且**你亲眼见过它先失败后通过**
- `pnpm typecheck` 无输出
- 已按计划原文 commit

### 回报格式

完成后按此格式回报，**不要写成散文**：

```
任务号：T<N>
状态：完成 / 受阻
新建文件：<路径列表>
修改文件：<路径列表>
测试命令与输出：<原样粘贴，不要概括>
commit：<sha> <message 首行>
偏差：<与计划不一致的地方；没有就写「无」>
接口摩擦：<实现过程中觉得 core 接口别扭/说不清的地方；没有就写「无」>
```

**「接口摩擦」这一栏是 P0 最值钱的产出，不要留空敷衍。** 它直接决定接口要不要改。

## 卡住时的升级路径

执行方遇到下列情况**立即停下上报，不要自行决断**：

- 计划里的代码跑不通，且原因不是自己写错
- 两个渲染器对同一份数据算出不同几何（T8 的 parity 测试红）
- 需要引入计划里没写的依赖
- 发现计划与 `AGENTS.md` / `docs/*.md` 的规则冲突

**特别地：parity 测试变红不是「测试有问题」，那是 P0 在正常工作。** 它说明两个实现对同一份数据理解不一致，这正是要找的东西。修完之后，差异必须记进 `docs/architecture.md` §8.2 实现成本对照表——那是选型结论的原始素材。
