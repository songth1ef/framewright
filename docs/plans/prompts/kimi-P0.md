## 4. 三条铁律（违反即打回重做）

1. **🔴 禁止把 node 对象整体展开进 Leafer 节点**——不许 `new Rect({...node})`、`Object.assign(ui, node)`。必须逐字段显式映射。
   理由不是洁癖：**LeaferJS 的 `x` `y` `width` `height` `rotation` `opacity` `visible` `name` `children` 与我方 node 字段全部同名**，展开会静默覆盖，且以后 node 加字段会悄悄泄漏进渲染器。这类 bug 表现为「莫名其妙渲染不对」，且两侧表现还不一样，是最难查的。
   计划里 `toLeaferProps()` 返回的是一个**只含 7 个几何字段的窄对象**，展开它是允许的——展开的是映射结果，不是 node 本身。
2. **🔴 任何切换后必须保留的状态都不能存在渲染器内部**——node 树、选中集、视口一律经 `RenderContext` 传入。渲染器内部只能持有 Leafer 实例、动画句柄这类纯呈现细节，`destroy()` 时全部释放干净（DOM、监听器、RAF 一个不留）。
3. **🔴 `packages/renderer-leafer` 不许依赖 `packages/renderer-dom`**，反之亦然。

另外：`packages/core` 是纯 TS 零渲染依赖，**不要往里加任何 leafer 相关的东西**。

## 7. Task 8 的测试规范（这三条违反一律打回）

1. **禁止 `waitForTimeout`。** 用 `expect(locator).toHaveText(...)` / `toHaveCount(...)` 这类会自动重试的断言。固定睡眠在慢机器上假失败、快机器上白等。
2. **选择器只用 `data-testid` 与 `data-fw-*`。** 不用 CSS class、不用文本内容、不用 DOM 层级路径——那三种一改样式就碎。
3. **禁止用截图像素比对做几何断言。** 抗锯齿与字体渲染在两个渲染器间天然不同，像素比对会给一堆假失败。几何一律用 `getRenderedBounds()` 的数字断言——这正是它作为正式接口存在的理由。

另外：每个用例自带前置，从 `page.goto('/')` 开始，不依赖别的用例留下的状态；用例之间必须能任意顺序、并行跑。

**几何基线文件必须提交进 git**，否则回归防线不存在。
