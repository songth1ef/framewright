- **不许扩大范围。** 计划末尾「P0 明确不做」那一节列的一律不碰。
- **commit message 用计划里给定的原文**，不要重写。每个 Task 结束提交一次。
- **不许 `git push`。** 只 commit。
- **不许 `--no-verify`** 或任何绕过校验的做法。测试不过就是没做完。

## 3. 三条铁律（违反即打回重做）

1. **🔴 禁止把 node 对象整体展开进渲染器**——不许 `new Rect({...node})`、`Object.assign(el, node)`、`<div {...node}>`。必须逐字段显式映射。
   理由：LeaferJS 的 `x` `y` `width` `height` `rotation` `opacity` `visible` `name` `children` 与我方字段全部同名，展开会静默覆盖并让新增字段泄漏。
2. **🔴 任何切换后必须保留的状态都不能存在渲染器内部**——node 树、选中集、视口、编辑中的输入一律在 `core` / 应用层，经 `RenderContext` 单向流入。渲染器内部只能持有 DOM 引用、Leafer 实例、动画句柄这类纯呈现细节，`destroy()` 时全部释放。
3. **🔴 上层不许出现渲染器品牌分支**——`apps/web` 里不允许写 `if (adapter.id === 'dom')` 之类。差异只能藏在渲染器包内部。

另有两条结构约束：

- `packages/core` **零渲染依赖**：不 import React，不 import leafer。
- 两个 `renderer-*` **互不依赖**，删掉任一个 `core` 仍能编译通过。

## 4. 版本

计划「版本选型」一节已给定精确版本，**照抄，不要自己取 latest**：

- TypeScript `^5.9.3`（**不用 7.x**）
- Next.js `15.5.22`（**不用 16.x**，精确版本无 `^`）
- react / react-dom `19.2.8`（精确版本无 `^`）
- leafer-ui `2.2.9`（精确版本无 `^`）
- Vitest `^4.1.10` / jsdom `^27.4.0` / @playwright/test `^1.62.1`

渲染相关依赖写精确版本是刻意的：本项目后续要产出可复跑的性能对照数字，版本漂移会让数字不可比。

## 5. 测试要求

- 一个测试只断言一件事；测试名写行为不写函数名
- 必须覆盖边界与否定用例，不能只测 happy path
- **每个映射函数必须有一条「不泄漏」测试**：断言 node 的 `fwId` / `fwType` / `locked` / `children` 没出现在渲染器属性里。这条是守铁律 1 的主力，不许省
- `core` 的每一个公开导出都要有测试——它是两个渲染器的共同地基，它错了两边一起错，对照实验测不出来
- 测契约不测实现细节

## 7. 卡住了就停

下列情况**立即停下上报，不要自行决断**：

- 计划里的代码跑不通，且原因不是自己写错
- 需要引入计划里没写的依赖
- 发现计划与 `AGENTS.md` 或 `docs/*.md` 的规则冲突

最后一条特别说明：**那不是「测试有问题」，那是 P0 在正常工作**，说明两个实现对同一份数据理解不一致——正是要找的东西。上报，不要自己抹平。
