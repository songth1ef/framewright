# interaction-spec — 画布交互规格

> **产品规格，不是实现方案。** 规定「用户怎么操作、看到什么反馈」，不规定用什么技术手段。
> 两个渲染器都必须照此实现，**不许各自发挥**——各自发挥造成的差异是「没对齐规格」，
> 不是「渲染方案差异」，会污染选型结论。
>
> 基准：Figma / 即梦 / liblib canvas 这类画布工具的通用交互习惯。这些是行业约定，
> 用户已有肌肉记忆，**不要创新**。
>
> 范围：P2 实现。契约见 `docs/architecture.md` §11。

---

## 1. 视口（无限画布）

| 操作 | 触发 | 行为 |
|---|---|---|
| 平移 | **中键按住拖拽** | 视口跟随移动，1:1 跟手 |
| 平移 | **空格按住 + 左键拖拽** | 同上（Figma 习惯，供没有中键的设备） |
| 平移 | **触控板双指滑动** | 同上 |
| 平移 | `Shift` + 滚轮 | 水平平移 |
| 缩放 | **滚轮** | **以光标位置为锚点**缩放 |
| 缩放 | `Ctrl` / `Cmd` + 滚轮 | 同上（兼容习惯） |
| 缩放 | 触控板捏合 | 同上 |
| 缩放 | `Ctrl` + `=` / `Ctrl` + `-` | 以视口中心为锚点，步进一档 |
| 适应内容 | `Shift` + `1` | 缩放到刚好容纳全部节点，四周留 5% 边距 |
| 实际大小 | `Ctrl` + `0` | 缩放回 100%，居中于内容 |

### 硬性规则

- **锚点缩放的定义**：缩放前后，**光标下的那个画布点必须停在原处**。这是「以光标为锚点」的唯一正确解释，也是最容易实现错的地方——错了的表现是画布会往光标反方向滑走。
- **缩放范围 `10%` – `400%`**。超出范围的输入被钳制，不是拒绝。
  - 不做 Figma 那种 1%–1600%：本项目是生成结果编排器，不需要看单个像素，也不需要俯瞰上万节点。
- **缩放步进按倍率，不按加法**：每格滚轮 `× 1.1` 或 `÷ 1.1`。线性加减会让放大时太慢、缩小时太快。
- **纯滚轮 = 缩放，不是垂直平移。**
  - ⚠️ 这一条与 **Figma 相反**（Figma 纯滚轮是垂直平移），但与**即梦 / liblib / Miro 等白板类工具一致**。本项目形态更接近白板，取后者。
  - 连带要求：必须 `preventDefault`，否则会触发浏览器页面滚动。
- **无限画布**：视口没有边界限制，可以平移到任意远处。但要提供 `Shift+1` 让用户能回到内容。

## 2. 选择

| 操作 | 触发 | 行为 |
|---|---|---|
| 单选 | 左键点击业务单元 | 替换选中集为该单元 |
| 增选 / 减选 | `Shift` + 左键点击 | 在选中集里切换该单元 |
| 框选 | **左键在空白处按下并拖拽** | 选中与选框**相交**的全部业务单元 |
| 框选增选 | `Shift` + 左键框选 | 把框中的并入现有选中集 |
| 全选 | `Ctrl` + `A` | 选中当前画板下全部业务单元 |
| 取消选中 | 左键点击空白 / `Esc` | 清空选中集 |

### 硬性规则

- **框选判定用「相交」不用「完全包含」**。这是 Figma 与绝大多数画布工具的行为，用户预期如此——要求完全框住会让大对象几乎选不中。
- **框选的起点决定行为**：起点落在**空白**→ 框选；起点落在**已选中的单元**→ 拖拽移动；起点落在**未选中的单元**→ 先选中它，再拖拽。这三种必须分清，是最容易做错的地方。
- **选中粒度恒为业务单元**，永不选中业务单元内部的元素（内部元素本就不在 node 树里，见 `docs/domain.md` §2.2）。
- **锁定（`locked`）的节点不参与点选与框选**，但仍然渲染。

## 3. 移动与尺寸

| 操作 | 触发 | 行为 |
|---|---|---|
| 拖拽移动 | 左键拖住已选中的单元 | 选中集**整体**移动，1:1 跟手 |
| 微调 | 方向键 | 移动 1px |
| 快速微调 | `Shift` + 方向键 | 移动 10px |
| 等比缩放 | 拖拽选中框的**四角**控制点 | 等比改变尺寸 |
| 删除 | `Delete` / `Backspace` | 删除选中集 |

### 硬性规则

- **🔴 只给四角控制点，不给边中点控制点——生成结果不允许被自由拉伸变形。**
  一张 AI 生成的图被拉成椭圆是产品事故，不是功能。要改比例只能重新生成。这一条是产品判断，不是技术限制。
- **拖拽过程是纯呈现**：移动预览由渲染器自己画，**不更新 node 树**。只在**松手时**提交一次 `onNodesMove`。
  逐帧提交会让一次拖拽产生几百条撤销日志（`docs/domain.md` §4.5）。
- **多选整体移动**：拖任意一个，整个选中集一起动，相对位置不变。

## 4. 其它

| 操作 | 触发 | 行为 |
|---|---|---|
| 激活 | 双击业务单元 | 打开该单元的生成参数面板 |
| 撤销 | `Ctrl` + `Z` | 见 `docs/domain.md` §4.5（持久化） |
| 重做 | `Ctrl` + `Shift` + `Z` | 同上 |

**不做**（`AGENTS.md` §1.1 主要矛盾）：右键菜单、剪贴板复制粘贴、对齐分布面板、图层面板拖拽排序、旋转控制点。

## 5. 视觉反馈

### 光标

| 状态 | 光标 |
|---|---|
| 空白处 | `default` |
| 中键按下 / 空格按下 | `grabbing` |
| 空格按住未拖动 | `grab` |
| hover 业务单元 | `move` |
| hover 四角控制点 | `nwse-resize` / `nesw-resize` |
| 框选进行中 | `crosshair` |

### 状态样式

| 状态 | 表现 |
|---|---|
| hover | 1px 淡色描边 |
| 选中（单个） | 2px 强调色描边 + 四角控制点 |
| 选中（多个） | 每个单元 2px 描边；**整个选中集外再套一个包围框**，控制点只出现在包围框上 |
| 框选框 | 半透明填充 + 1px 实线边 |

### 硬性规则

- **描边与控制点不随画布缩放而变粗变细**——缩放到 400% 时选中框仍是 2px 视觉宽度。这需要按 `1 / viewport.scale` 反向补偿，两侧都要做，是个常见坑。
- **控制点的尺寸同理**，恒为固定的视觉像素。
