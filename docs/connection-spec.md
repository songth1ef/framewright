# connection-spec — 溯源连线视觉规格（M2）

> **`sourceFwIds` 表示的派生关系怎么画。两个渲染器照此实现，不许各自发挥。**
>
> 语义见 `docs/domain.md` §3.2.2：连线 = **「派生自」**，记录一个生成结果从哪个节点来。
> 用户原话：*「图片后面出 abc 版本三个视频，那么连线就是说这三个视频的来源都是这张图片。」*
>
> 适用：波次 2 的 C2-dom / C2-leafer。

---

## 1. 连线不是 node

**这条决定了后面所有细节。**

- 连线**不进 node 树**，没有 `fwId`、没有 `x/y/width/height`
- 连线的位置**完全由两端节点的几何算出来**，不单独存储
- **首版不可选中、不可点击、不可删除**（要断开来源，将来在节点上操作）
- 连线**不进 `getRenderedBounds()`**，因此不影响 parity 断言

## 2. 画在哪一层

**连线画在所有节点的下方**（z 序最底），这样节点永远压在连线之上，不会被线穿过内容区。

DOM 侧与 Leafer 侧都需要一个独立的「连线层」，位于节点层之下、视口 transform 之内（连线要跟着画布一起平移缩放）。

## 3. 几何：从哪连到哪

对每个生成单元的 `sourceFwIds` 里的每一项，画一条从**源节点**到**本节点**的曲线。

**锚点固定在两个节点的边中点**，不做智能选边：

- **起点** = 源节点的**右边中点** `(src.x + src.width, src.y + src.height / 2)`
- **终点** = 本节点的**左边中点** `(self.x, self.y + self.height / 2)`

坐标一律用**画布绝对坐标**（`walkTree` 已提供累加）。

> **为什么不做智能选边**：源在右、派生在左时线会绕回去，视觉上确实不如智能选边。但智能选边需要一套「哪条边最近」的判定，两侧实现极易分叉，而它对**选型结论零贡献**。首版固定右→左，差异如实记进成本表。

## 4. 曲线形态：三次贝塞尔

```
起点 P0 = (x0, y0)
控制点 C1 = (x0 + k, y0)
控制点 C2 = (x1 - k, y1)
终点 P3 = (x1, y1)

k = clamp(|x1 - x0| * 0.5, 40, 160)
```

即：**两个控制点水平外推**，外推距离取两点水平距离的一半、钳制在 `[40, 160]`。

这样近距离时线不会鼓得太夸张，远距离时也不会拉成一条直线。**`k` 的公式两侧必须一致**——它决定曲线胖瘦，肉眼可见。

## 5. 样式常量

放 `packages/core/src/connection-style.ts`，两侧 import，**不许各自硬编码**：

```ts
export const CONNECTION_STYLE = {
  strokeColor: '#B8B8C4',
  strokeWidth: 1.5,
  /** 端点小圆点半径；0 表示不画 */
  endpointRadius: 3,
  endpointColor: '#B8B8C4',
  /** 源节点或本节点被选中时，连线高亮 */
  highlightColor: '#5B8091',
  highlightWidth: 2,
} as const
```

## 6. 高亮规则

**当连线的任一端节点在选中集里时**，整条线用 `highlightColor` / `highlightWidth`，否则用常态色宽。

这让用户选中一张图时，能一眼看出「它派生出了哪些东西」。

## 7. 🔴 不随画布缩放变粗

与选中描边同一条规则（`docs/interaction-spec.md` §5）：**`strokeWidth` 恒为视觉像素宽度**，缩放到 400% 时不能跟着变粗。

两侧各自按 `1 / viewport.scale` 反向补偿，或用各自的等效机制（Leafer 侧可先验证 `scaleFixed` 是否对 `strokeWidth` 生效——那是 `renderer-contract.md` §6 的遗留项 1）。

## 8. 悬空引用

`sourceFwIds` 里的 id 在树里**找不到对应节点**时（源已被删除），**跳过这条线，不画、不报错**。

数据层的清理是 `server-core` 的职责（`domain.md` §3.2.2 悬空引用一节），**渲染器不负责修数据**，只负责画不出来就不画。

## 9. 离群节点

对标产品有「有 5 个离群节点 · 定位下一个 (1/5)」的提示。

**离群 = 生成单元中 `sourceFwIds` 为空、且没有任何节点的 `sourceFwIds` 包含它。**

**首版不做这个提示** ——它属于应用层 UI（工具栏区域），不是渲染器的事，且对选型结论零贡献。判定逻辑将来放 `core`（纯数据计算，两侧共享），登记为后续项。

## 10. 两侧允许不同的地方

- 曲线的绘制手段（SVG `<path>` vs Canvas `bezierCurveTo`）
- 连线层的组织方式（一个 SVG 容纳全部 vs 每条一个元素）
- 高亮的实现（改属性重绘 vs 双层叠加）

**统一要求的只有：锚点位置、`k` 的公式、颜色、线宽、层次（在节点下方）、高亮触发条件。**

## 11. 验收

1. demo 文档里那组溯源关系（1 个 `ai-image` → 2 个 `ai-video`，B1 已建）**两侧各画出两条线**
2. 两侧的**曲线端点坐标一致**——写一条测试，把两侧算出的 `(P0, C1, C2, P3)` 四点做数值比对
3. 选中源节点时**两条线同时高亮**；选中其中一个派生节点时**只有那一条高亮**
4. 缩放到 400% 时线宽视觉上不变粗
5. 人为把某个 `sourceFwIds` 指向不存在的 id → **不画、不报错、其余线正常**
