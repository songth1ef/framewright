| 链路 | 状态 | 卡在哪 |

| **🔴 画布内容自动保存** | ⬜ | **F6 没做** |

### F6 没做的具体后果

`server-history.ts` 第 12 行的注释写得很明白：

> *「平时的 `historySeq` 持久化由 Document **防抖保存（F6）**携带 `getHistorySeq()` 完成」*

**也就是说**：`document.root`（画布内容本身）**只在「撤销之后又产生新操作」这一条特定路径下才被 `PUT` 一次**，平时的拖动、缩放、删除**都不写回 document**。

**实际表现**：

- 操作日志在后端 ✅
- 但 `document.root` 停留在旧状态
- **刷新页面 → 画布内容回到旧的** ❌
- 连带「跨会话撤销」也用不成——日志对得上，内容对不上

**这就是你体感「自动保存和撤销都没做」的真实原因**：撤销的后端写入做了，**但没有自动保存兜底，整条链在实际使用中是断的**。

### 🔴 一条必须记住的：首轮 Leafer 性能数据全部作废

探针跑出 1/4/8 路并发 **60.12 / 59.72 / 58.99 fps、长帧 0** 的漂亮成绩单。
**但同一份 JSON 里画面指纹两次完全相同、内存三档都是 9.5MB、8 路里只有 4 路在走** ——
视频根本没渲染到画布上，那三个 fps 测的是空转的 rAF 循环。

**空转的 60fps 和真干活的 60fps，数字上完全一样。**

此后任何视频/动画基准必须带「东西真的在变」的证据（画面指纹 / 解码帧计数 / 随负载上升的内存），
否则不采信。详见 `architecture.md` §8.2。
