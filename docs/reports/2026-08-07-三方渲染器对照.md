## 🔴 三条结论（读表之前先看）

### ① DOM 在 A 层 15 个组合里**全部 60fps，无一例外**

另外两方都有明显掉帧档位。这是本次最干净的一条。

### ② React Flow 在低缩放 + 大节点数下崩溃，且内存是灾难性的

10000 节点 @10%：**2.8 fps / renderer 内存 +1232MB**，而 DOM 是 60.0 fps / +308MB。
内存 4 倍、帧率 1/21。

**关键：这是在已经用我们自己的裁剪预处理过之后的数字。** §8.9.2 曾测出
「先裁剪后 React Flow 和我们一样快（60fps）」—— **那是 1000 节点 @100% 的单点**。
全矩阵跑完才看到它在低缩放 + 大节点数下依然崩溃。

→ **单点不能外推到矩阵。** 这条和「一侧的优化收益不能外推到另一侧」是同一类错误，
只是这次跨的是场景维度而非渲染器。

对竞品的推测（仍未验证）：liblib 用的就是 React Flow。
若他们的画布支持缩到很小且节点上千，会遇到同样的墙。

### ③ Leafer 的内存优势是真的，但**用帧率换来的**

| 组合 | Leafer 内存 | DOM 内存 | Leafer 平移 | DOM 平移 |
|---|---:|---:|---:|---:|
| 10000 @100% | **192MB** | 305MB | 60.1 | 60.0 |
| 10000 @10% | **163MB** | 308MB | **36.3** | 60.0 |
| 10000 @25% | 239MB | 216MB | **28.5** | 60.0 |

10% 档它省 47% 内存但掉到 36.3fps；25% 档内存没优势、帧率还掉一半。
**内存优势只在特定档位成立，不是普遍属性。**
