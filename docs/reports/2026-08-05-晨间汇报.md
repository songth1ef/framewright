### 🔴 最值得你亲手试的三件事

1. **`Ctrl`+滚轮时盯住光标下那个点**——两侧都应纹丝不动。这是视口数学里最容易写错的地方。
2. **拖动画布后立刻切换渲染器**——视口和选中应该原样保留。这是「状态不许存在渲染器内部」那条铁律的可见验证。
3. **对比两侧的跟手感**——机器只比 `getRenderedBounds()` 的数字，**骨架屏动画、连线曲线胖瘦、拖拽跟手程度这些它一个都测不出来，只有你能判断**。

### 1. 🔴 「用现成方案 vs 继续自建」

**背景**：你观察到竞品基本都用 DOM，让我调研有没有开箱即用的。

**已查明**（`docs/research/2026-08-04-canvas-vs-dom.md`）：

- **ComfyUI 正在从 Canvas 迁往 DOM**（官方 2025-12），理由是 canvas「限制了 UI 能做什么」——**这是在 AI 生成节点画布这个完全相同的场景里做的反向迁移**
- **tldraw 的混合切法与直觉相反**：图形在 **DOM**，`<canvas>` 只画临时 overlay（选择框、笔刷、吸附线）
- **tldraw 官方把 Luma 和 Runway 列为客户**——两家都是 AI 图片/视频生成产品

**你的判断**（2026-08-04）：React Flow 不合适，因为它的心智模型是「图」不是「编辑器」，而你对标的是**客户端级手感**（即梦 / liblib，参照物是剪映和 Figma）。

**我认同，并补充最要命的一条**：你的连线是**生成动作的副产品**，不是用户拖出来的；而 React Flow 整个交互模型建立在「用户拖句柄连线」上——用它就得一直跟这个假设打架，**深度定制反而比自建贵**。

**✅ 第二份调研已回**（`docs/research/2026-08-04-ready-made-libs.md`），三条决定性的：

| 发现 | 含义 |
|---|---|
| **tldraw license 已证实禁止闭源商用生产使用** | ❌ **出局**。技术最贴合也没用 |
| **端口税比预想小**——边只需 `{source, target}` 两个 id，句柄只是每节点一个隐形 `div` | 我之前说「会被迫吃下整套节点图语义」，**夸大了** |
| **🔴 调研过的所有库，没有一个有官方示例演示节点内嵌 `<video>` 播放器** | 全部「未找到公开依据」 |

**第三条是你那个判断的独立佐证**，而且比「框架心智模型不对」更硬：

> **不是「框架不够好」，是没有任何框架趟过你最关键的那条路。**
> 选任何库，视频节点的内存治理、懒挂载、多路并发**都得自己写**——而那恰恰是最可能决定成败的地方。

另外**撤销这项各库的差异对我们已经无效**——React Flow 要自研、LogicFlow 内置，但**我们已经写完了**（`core/history.ts` + 跨会话持久化）。

⚠️ 顺带一个灰区留档：React Flow 的 attribution（水印）**官方只说过「订阅 Pro 后允许移除」，从没说过「不订阅也能移除」**。要去水印是 **$169/月起**。调研中出现过一条相反说法，逐页核实后查不到、已推翻——**license 一栏宁可标「未证实」也不写进结论**。

## 四、值得你知道的技术判断

### 1. 五个设计空洞，全部在写代码之前被抓到

Codex 五次因「设计有缺口」停下上报，**每次都是真问题**：

1. `onNodeAction` 依赖了尚未存在的 `callbacks` 接口
2. 连线层序：「画在所有节点下方」没定义画布底色算哪层——**Kimi 实现时踩了，连线被白底整个盖住，而所有测试都是绿的**
3. 多选等比缩放缺 core 映射函数，且 `minSize` 从没钉过值
4. `remove-node` 的逆操作丢信息，撤销删除时连线恢复不回来
5. `InboundRef` 缺被引用目标 id，删 frame 时后代的引用无法无损恢复

**共同点：我写规格时下的每个「必然如此」的断言，都没有逐项验证。** 已在 `domain.md` 里记了一笔自嘲。

### 2. 一个 parity 测不出来的 bug，靠截图抓到

Kimi 把连线画在了画布底色下面，**完全不可见，但所有测试都绿**——因为连线不进 `getRenderedBounds()`，parity 摸不到它。它跑 Playwright 截图目视才发现。

**教训**：机器只能验它被告知要验的东西。

### 3. 🔴 刚抓到一个更危险的：测试存在但永远不跑

Codex 给 API 路由写了 17 条测试，**在 `pnpm verify` 里根本不执行**——因为路径 `apps/web/app/api/documents/[id]/route.test.ts` 里的 `[id]` 被 glob 当成了字符集。

实测：全量跑 30 文件 268 测试**不含它们**；`--project web` 单跑能出 2 文件 17 测试。

**比测试失败危险得多——它存在、单跑能过、看起来有覆盖。** Next.js 的 App Router 到处是 `[id]`，这坑后面还会踩。已排进修复任务。

### 4. LeaferJS 的两条实测结论

- **`scaleFixed` 对 `strokeWidth` 不生效**（源码佐证 `UIRender.ts` 只读 `shadow.scaleFixed`）→ 描边不随缩放变粗只能手写 `1/scale`
- **内建手势的真实风险面远小于文档推测**：`config.move` 的五个开关默认全关、`zoom.min/max` 本版本根本没被读取、wheel handler 对 transform 是 no-op

### 5. 🔴 一个把两个 agent 都卡住的 bug，以及它为什么难查

**症状**：首页 500，`TypeError: Cannot read properties of undefined (reading 'indexOf')`，**没有 stack**。

**两个 agent 先后栽在这里**——Codex 的 `pnpm verify` 连续两次不绿、按收敛线停下；Kimi 被卷进去查了很久（推测 WASM 路径解析、`require.resolve` 失败…），最后任务失败中断。

**根因**：`server-core/prisma.ts` 的默认 `DATABASE_URL` 是 **相对 cwd** 的（`file:./prisma/dev.db`），而 **Next dev 的 cwd 是 `apps/web` 不是仓库根**。

**为什么难查**：Node 里报的是「Cannot open database because the directory does not exist」，**穿过 Prisma 的 WASM 边界后被改写成了 `indexOf of undefined` 且丢掉 stack**。从症状根本反推不回去。

**怎么找到的**：不是继续读代码猜，而是**设计了一个能区分假设的实验**——同一段 `document.count()`，跑「四种 URL 形式 × 两种 cwd」的矩阵：

| | cwd = 仓库根 | cwd = `apps/web` |
|---|---|---|
| `file:./prisma/dev.db` | ✅ | ❌ 目录不存在 |
| `file:E:/.../dev.db` | ✅ | ✅ |
| 无前缀绝对路径 | ✅ | ✅ |
| `file:///E:/.../dev.db` | ❌ | ❌ |

**数据自己指出了哪个维度是相关的。**

**连带教训（已写进任务板）**：验证必须端到端。**单测在仓库根 cwd 下本来就是绿的，测不出这个 bug**——这类「只在某个运行环境下才暴露」的问题，单元测试天然看不见。

### 6. 我自己犯的错，记在这里

- 说「Canvas 里没有 `<video>`」——**没查过 LeaferJS 就下结论**，实际它有完整的 `IVideoDecoder`。是你凭印象提醒才发现的
- 引用「canvas 里的像素放不了下拉菜单」当作 React Flow 官方立场——**追溯不到官方出处**，只是二手博客
- 把 Kimi「demo 文档没嵌套」的说法直接写进文档——**读原文发现不成立**

- 排期错误：同时派两个 agent 动数据库层，理由是「文件领地不重叠」——**但 Prisma client、SQLite 文件、迁移历史、`node_modules`、端口 3100 都是共享运行时状态，文件隔离对它们无效**。已改成「同一时刻只允许一个 agent 动数据库层」
- 查上面那个 500 时，我先猜是模块解析问题（`server-core` 是 TS 源码包却被放进 `serverExternalPackages`），改完一测**错误一模一样**——那个改动本身是对的但不是根因

**共同的毛病：有现成的东西可以打开看、有实验可以做，我却用推的。** 好在最后一次纠正得快——**真正解决问题的不是更聪明的猜测，是那个矩阵实验。**
